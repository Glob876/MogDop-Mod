# MogDop-Mod — правила разработки

## 1. Новая функция → вопрос про конфигурацию

При добавлении любой новой функции первым делом решить: **нужна ли ей конфигурация**.

- Если у функции есть хоть один настраиваемый параметр (вкл/выкл, число, цвет, размер) — он идёт в конфиг, а не в хардкод.
- Конфиг: поле в `common/.../client/MogdopsModConfigModel.java` (с `@RangeConstraint` для чисел).
- Fallback: `MogDopSModClient.initConfig()` — рефлексивный proxy, новые поля подхватываются сами; вложенные секции — обычным классом с публичными полями (OWO вернёт саму модель из `CONFIG.chat()`-подобного метода).
- UI: настройка добавляется в `SettingsTab` (`SpawnerScreen.java`) — тоггл/степпер/колорпикер.
- Локализация: ключи в `ru_ru.json` + `en_us.json` (`assets/mogdopsmod/lang/`).
- Значения читаются из конфига напрямую каждый кадр, где нужен live-эффект (превью без сохранения до закрытия экрана).

## 2. Никакого спагетти и монолитов

- Один класс/файл — одна ответственность. Новую подсистему (рендер, сеть, UI-экран, менеджер) — в отдельный класс, а не методом в существующий.
- Большие экраны (`SpawnerScreen` и подобные): логика вкладок — по приватным inner-классам/модулям, общие виджеты — в статические хелперы (`createFlatButton`, `smallLabel`, `chatIntRow`), а не копипастой.
- Общая переиспользуемая логика — в хелперы/менеджеры (`client/`, `client/render/`), а не дублированием между Fabric/NeoForge.
- **Исключения** (им можно быть толстыми): gradle-скрипты и главные классы — `MogDopSMod` и `MogDopSModClient` (точка входа, статическое состояние, регистрация).

## 3. Структура директорий вместо кучи файлов

- Не складывать много файлов одну функцию в одну директорию: если несколько файлов обслуживают одну фичу — им отдельная поддиректория.
- Ориентиры: `client/gui/` — только экраны/HUD; `client/render/` — рендереры и текстуры; `network/` — пейлоады; `entity/` — сущности.
- Пример: новая система «X» из 3+ файлов → `client/x/XManager.java`, `client/x/gui/...`, а не пять файлов в корне `client/`.

## 4. Проверка

- После изменений: `./gradlew :fabric:build` (только fabric; NeoForge временно сломан — не трогать).
- Коммиты — по шагам, один логический шаг — один коммит.
